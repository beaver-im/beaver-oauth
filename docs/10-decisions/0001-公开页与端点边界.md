# ADR 0001 公开页与端点边界

- 状态：Accepted
- 日期：2026-11-25
- 范围：beaver-oauth 浏览器前端与 beaver-server-open 公开接口

## 背景

授权页由第三方浏览器直接访问，不能持有客户端密钥。扫码确认需要登录用户，必须在 App 内完成。
若前端调用受信任接口或自行实现 code 换 token，会把服务端权限带入公开产物。

## 决策

本仓只实现公开授权页与扫码引导，自有网络请求限定为：

- GET `/api/open/oauth_public/v1/qrcode_scene`
- GET `/api/open/oauth_public/v1/qrcode_status`（函数已实现，当前无调用方）

登录组件与授权交互交给 `@beaver-im/js-sdk`。App 内扫码/确认、回调白名单、code 签发与 token 交换由服务端和 App 承担。
前端不得出现 appSecret、S2S 票据或 code 换 token 请求。

## 理由与取舍

公开端只能使用无需客户端密钥的能力，降低密钥泄露与越权风险。
代价是本仓不能独立完成授权全流程，联调依赖 SDK、App 与 open 服务；status code 的消费也必须由可信流程定义。

## 备选方案

- 前端保存 appSecret 并换 token：泄露风险不可接受，未采用。
- 浏览器完成扫码确认：缺少可信登录身份，且改变产品边界，未采用。
- 复制 SDK 登录逻辑：重复实现且难与授权码流程一致，未采用。

## 影响与生效条件

新增接口先确认是否属于 `oauth_public` 且不需要秘密。`redirectUri` 白名单、code 一次性、限流与 CORS 由服务端保证。
`qrcode_status` 若接入轮询，必须另定停止、取消、code 消费与防重放规则，不能直接写入 URL 或存储。
