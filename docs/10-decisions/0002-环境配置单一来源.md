# ADR 0002 环境配置单一来源

- 状态：Accepted（现状约束，键名修复待单独任务）
- 日期：2026-11-25
- 范围：`.env.*`、`src/config/env.ts`、`vite.config.ts`

## 背景

项目有 dev/test/prod 三套环境，历史上 README 使用 development/production，源码脚本使用 dev/prod。
env 文件写 `VITE_API_ENV`，代码读取 `VITE_APP_ENV`，导致环境展示值为 undefined。
API 基址与 mode 如果各有一套来源，容易出现请求错环境或静默兜底。

## 决策

- `.env.dev`、`.env.test`、`.env.prod` 是环境文件唯一来源，mode 与文件名一致。
- `VITE_API_BASE` 是唯一 API 基址，经 `requireEnv` 强校验，不提供默认域名。
- 运行时配置统一从 `src/config/env.ts` 取；Vite define 只注入约定的 `VITE_APP_ENV`。
- 当前 `VITE_API_ENV`/`VITE_APP_ENV` 不一致作为已知现状记录，不在文档任务中擅自改代码或部署。

## 理由与取舍

集中配置便于审计目标环境，缺失即失败可避免请求静默落到错误服务。
保留现有不一致是为了让修复涉及 env、源码、构建和部署时可整体评审，而不是只改显示值。

## 备选方案

- 多套默认域名兜底：可能掩盖配置错误，未采用。
- 在页面硬编码环境判断：扩散且难以审计，未采用。
- 仅把 env 键改成 VITE_APP_ENV：表面修复但可能破坏外部注入，需部署协同，未采用。

## 影响与生效条件

正式修复时同时更新三份 env、env.ts、vite.config.ts、部署变量、README/手册与验证矩阵，
并验证三种 mode 的 config.env、define 和请求基址。任何环境变量都不得包含密钥。
