# 8.1 构建与发布

[返回本章](README.md) · [全书目录](../README.md)

## 构建命令

| 命令 | 作用 |
|---|---|
| `npm run dev` | 以 dev env 启动 Vite，端口 8045 |
| `npm run serve_test` / `serve_prod` | 用对应 env 启动开发服务器 |
| `npm run build_test` | `vue-tsc -b` 后以 test mode 构建 |
| `npm run build_prod` | `vue-tsc -b` 后以 prod mode 构建 |

没有 build_dev。`vue-tsc -b` 会检查 tsconfig 的 app/node 两个引用；任一侧失败不会继续 Vite build。
tsbuildinfo 写在 `node_modules/.tmp/`，不是发布产物。

## 产物

`dist/` 由 `.gitignore` 排除，不手改、不提交。Vite `base: './'` 生成相对资源路径，适合静态托管子目录。
构建只证明类型检查与打包通过，不证明 SDK、CORS、公开接口、回调白名单或 History 回退正确。

`package.json` 与 `VERSION` 都是 `2.0.2`；发版时同步两者，并检查 README 版本徽章。
`private: true` 表示不发布 npm 包；这里的发布指静态前端部署。

## 发布前检查

1. 用目标 mode 构建，确认无类型错误与密钥进入产物。
2. 检查资源基址、`VITE_API_BASE` 与 SDK apiBase 指向目标服务。
3. 配置 HTTPS、CORS、History 路由回退与缓存策略。
4. 验证 `/auth`、`/scan` 直接访问和刷新、移动端布局、SDK 登录与 App 扫码确认。
5. 验证失败场景与错误文案，不把业务失败当部署成功。

本仓没有 Dockerfile、CI 工作流、部署脚本或签名流程；不要引用其它仓的发布命令。

## 锁文件

`package-lock.json` 与 `pnpm-lock.yaml` 并存，现有脚本用 npm。除非明确迁移，不混用包管理器。
安装会触发 Husky prepare；构建前检查工作树，避免把依赖或生成物变化混入功能改动。
