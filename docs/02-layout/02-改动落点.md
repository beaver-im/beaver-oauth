## 最小改动原则

优先复用现有 API/config/request 三层，不新增全局状态库或第二套 HTTP 客户端。
页面组件已经承载本地状态；只有出现跨页共享且可持续维护的状态时，才讨论 store，并同步安装 Pinia、修改 main 与 AutoImport。

新增环境时同时增加 `.env.<mode>`、npm script（若需要）、部署配置与[第 3 章](../03-config/)说明。
不要创建 `.env.development` 后仍运行 `--mode=dev`，两者不会自动匹配。

## 旧文件处理

`CONTRIBUTING.md`、`SECURITY.md` 含 manager 模板内容，不作本仓开发规范。
`OAUTH_README.md` 只作历史流程背景；端口、路由、SDK 包名与换 token 示例均不能当现状。
发现代码与旧文档冲突时，以源码为准并修正工程手册，不扩散旧示例。
