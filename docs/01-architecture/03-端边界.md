# 1.3 端边界

[返回本章](README.md) · [全书目录](../README.md)

## 浏览器前端负责

- 从 URL 读取 `oauthId`、`redirectUri`、`sceneId`。
- 注册 Beaver SDK，把公开授权参数交给 `<beaver-login>`。
- 查询公开扫码 scene，展示应用名与 App 内确认引导。
- 通过统一 axios 实例调用 `oauth_public` GET，并展示少量页面错误。

## 浏览器前端不负责

- 不持有 `appSecret`、内部 S2S 票据或长期用户 token。
- 不实现 code 换 token、权限授予、扫码确认或二维码签发。
- 不调用 `/oauth/v1/*`、`/secret_public/v1/*` 等需要信任身份的接口。
- 不自行拼接第三方回调域名，不把 URL 参数写入日志或持久化。

扫码页的“确认授权”由海狸 IM App 完成；浏览器页只显示引导。
`checkQrCodeStatusApi` 虽已实现且服务端会返回 code，当前页面未调用，不构成前端轮询或自动跳转流程。

## SDK 边界

授权页把 `oauth-id`、`api-base`、`redirect-url` 传给 SDK 组件。
本仓不校验账号、密码、验证码或最终授权结果，也不应复制 SDK 内部请求到 `src/api/oauth.ts`。
`redirectUri` 当前可由 query 任意提供并交给 SDK；其合法性与允许列表必须由服务端/SDK 授权流程约束。

## 部署边界

本页可由浏览器直接访问，所有 `VITE_*` 值都会进入客户端产物。
因此环境文件只放公开基址与环境名，禁止放密钥。静态托管需支持 History 路由回退与 HTTPS；
CORS、公开端点限流、回调白名单和 token 交换属于服务端职责。

相关决策：[ADR 0001](../10-decisions/0001-公开页与端点边界.md)。
