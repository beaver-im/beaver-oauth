# 5.2 扫码页

[返回本章](README.md) · [全书目录](../README.md)

## 当前流程

`/scan` 在 `onMounted` 读取 `sceneId`：

1. 缺失时设置 `error='sceneId 缺失'` 并返回。
2. 调用 `getQrCodeSceneApi(sceneId)`。
3. `res.code !== 0` 时显示 `res.msg || '二维码已失效'`。
4. `res.result` 缺失时显示「扫码会话不存在」。
5. 成功时取 `appName`（空值回退「第三方应用」），设置 `loaded=true`。

模板显示“请打开海狸 IM，在 App 内确认授权”和“浏览器无法完成扫码确认”。
这是引导页，不是二维码生成页，也不是浏览器轮询页。

## 状态处理边界

Scene DTO 有 waiting/scanned/confirmed/cancelled/expired 与 `expireIn`，但页面当前不按状态分支。
即使 scene 已 confirmed、cancelled 或 expired，只要接口 `code=0` 且有 result，仍可能展示引导。
`appIcon`、`oauthId`、`scopes` 当前不渲染。`qrcode_status` 与 `code` 当前不参与页面逻辑。

## 已知异常缺口

`await getQrCodeSceneApi` 没有 try/catch。网络失败、超时或 axios reject 会产生未处理的 promise rejection，
不会自动进入页面错误状态。HTTP 200 的业务失败有处理，两者不能混为一谈。

新增重试、过期倒计时或状态轮询前，需要定义轮询停止条件、取消请求、页面卸载清理与 code 消费边界。
不要在没有产品与安全确认时把 code 写入 URL、localStorage 或日志。

## 验证

覆盖 sceneId 缺失、业务 code 非 0、result 为空、网络 reject、超时、过期、已确认、取消和 App 名称缺失。
检查错误文案不泄露服务端内部信息，且不会在失败时展示“已就绪”卡片。
