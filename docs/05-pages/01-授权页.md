# 5.1 授权页

[返回本章](README.md) · [全书目录](../README.md)

## 入参

`/auth` 从 `window.location.search` 读取：

| 参数 | 用途 | 当前校验 |
|---|---|---|
| `oauthId` | 传给 SDK 的第三方应用标识 | 空值显示错误并隐藏卡片 |
| `redirectUri` | 传给 SDK 的第三方回调地址 | 无前端校验，空值也传递 |
| `apiBase` | 不来自 query，固定取 `config.baseAPI` | env 必填 |

页面不读取 `scope` 或 `state`。OAuth 状态参数校验与 scope 授予由 SDK/服务端流程承担，
不能在旧 README 基础上声称本页已实现完整 state 防 CSRF。

## 渲染与 SDK

setup 创建三个 ref 与 `pageError`；模板在错误时显示提示，否则渲染 `<beaver-login>`。
`onMounted` 先调用 `BeaverSDK.register()`，再检查 `oauthId`。
因此即使最终显示缺参错误，SDK 也会先注册；调整顺序前确认 SDK 的全局副作用。

`beaver-login` 不是本仓组件。其 props 为 `oauth-id`、`api-base`、`redirect-url`。
本仓不实现账号输入、密码校验、授权确认或最终重定向。

## 当前缺口

- `redirectUri` 未做协议/域名/空值检查，只转交 SDK。
- SDK register 或组件异常没有本仓 catch/错误上报。
- 没有 loading、取消、重复挂载或授权结果回传处理。
- 页面文案与样式可独立维护，但新增流程必须确认 SDK 支持，不能复制旧 token 示例。

## 验证

至少覆盖：缺 oauthId、正常 oauthId、空/非法 redirectUri、SDK 加载失败、CORS、移动端视口。
完整授权码流程需 SDK 与服务端联调；仅构建通过不能证明授权成功。
