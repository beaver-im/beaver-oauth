# 7.1 错误与上报

[返回本章](README.md) · [全书目录](../README.md)

## 当前诊断手段

- `config/env.ts` 用 `console.info` 输出环境名与 API 基址。
- 授权页用 `pageError` 显示缺 oauthId。
- 扫码页用 `error` 显示缺 sceneId、业务失败和空 result。
- axios reject 直接向调用方传播，没有全局 UI 或上报。
- 没有 Logger、Sentry、埋点、错误边界或统一告警。

环境日志中的基址是公开配置，但生产日志策略仍应避免输出 query、授权 code、token 或完整 SDK 错误对象。

## 异常分类

| 情况 | 当前结果 |
|---|---|
| `VITE_API_BASE` 缺失 | 模块加载抛错，应用启动链阻断 |
| 缺 oauthId | 页面错误卡片 |
| SDK register 抛错 | 无本仓捕获 |
| 缺 sceneId | 页面错误文案 |
| scene HTTP reject/超时 | onMounted async 未捕获，页面无错误兜底 |
| scene `code !== 0` | 显示 msg 或默认过期文案 |
| scene result 为空 | 显示会话不存在 |
| status 接口失败 | 当前无调用方 |

## 排障顺序

1. 检查浏览器 Network 中实际 mode、API 基址、请求 URL 与 CORS。
2. 区分启动配置异常、SDK 异常、HTTP reject 与业务 `code !== 0`。
3. 检查 URL 参数是否存在，是否被错误编码或重复消费。
4. 对扫码页确认 promise rejection 是否被浏览器控制台记录。
5. 检查静态托管 History 回退，避免把 404 误判为 Vue 路由问题。

## 新增上报要求

不得上报完整授权 URL、code、token、appSecret 或 SDK 请求体。
若引入错误平台，需要脱敏、采样、用户告知与环境隔离，并更新手册；当前没有这类能力，不宣称已监控。
