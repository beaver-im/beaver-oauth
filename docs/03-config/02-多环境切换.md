# 3.2 多环境切换

[返回本章](README.md) · [全书目录](../README.md)

## mode 与脚本

| 脚本 | 实际命令 | 是否类型检查 |
|---|---|---|
| `dev` | `vite serve --mode=dev` | 否 |
| `serve_test` | `vite serve --mode=test` | 否 |
| `serve_prod` | `vite serve --mode=prod` | 否 |
| `build_test` | `vue-tsc -b && vite build --mode=test` | 是 |
| `build_prod` | `vue-tsc -b && vite build --mode=prod` | 是 |

Vite `loadEnv(mode, process.cwd(), "")` 加载全部键，不只是 `VITE_` 前缀；
客户端暴露仍遵循 Vite 的 `import.meta.env` 规则。`define.__APP_ENV__` 显式注入 `VITE_APP_ENV`，当前缺键。

## 本地服务

开发服务器 `host: true`、端口 `8045`。`host: true` 可能监听局域网，只应在可信网络使用。
`serve_prod` 只是用 prod env 启动 Vite 开发服务器，不是生产静态部署，也不会执行 `vue-tsc`。

## 切换检查

1. 确认 mode 与 `.env.<mode>` 文件对应。
2. 确认 `VITE_API_BASE` 非空且路径前缀正确。
3. 检查 `VITE_API_ENV`/`VITE_APP_ENV` 不一致是否已处理。
4. 构建后检查 `dist/` 中请求基址指向目标环境，不包含密钥。
5. 部署后验证 `/auth` 与 `/scan` 深链刷新、CORS、SDK 与公开接口。

新增环境不得只复制脚本；还要补 env 文件、部署变量、文档与验证矩阵。锁文件有 npm/pnpm 两份，
但现有脚本按 npm 编写，除非项目明确迁移，不凭空写 pnpm 命令。
