# 9.1 任务顺序

[返回本章](README.md) · [全书目录](../README.md)

## 标准顺序

1. 确认改动属于页面、路由、公开 API、SDK 还是环境配置，先读对应源码与章节。
2. 接口改动先核对服务端 `.api`/handler/types，再补 DTO 与 API，不在页面直接请求。
3. 保持网络三层：页面 → `api/oauth.ts` → `utils/request`；地址只从 config 取。
4. 同时处理业务 `code !== 0`、HTTP reject、空 result 与缺 query，不能只覆盖成功路径。
5. 按[9.2](02-验证矩阵.md)执行只读检查、构建与浏览器场景，记录未执行项。
6. 同步目录、章首、全书目录、knowledge-checks 与 AGENTS 任务入口。

## 安全与边界评审

- 新字段是否只应存在于公开响应，不能带 appSecret/token？
- `redirectUri` 与 code 是否会被写入 URL、日志或存储？
- 新接口是否仍属于 `oauth_public`，是否需要身份但被错误暴露？
- SDK 是否已提供能力，避免复制一套登录/授权逻辑？
- 错误文案是否泄露内部地址、堆栈或服务端细节？
- History 深链与静态回退是否已验证？

## 旧资料冲突

遇到根 README、OAUTH_README、CONTRIBUTING、SECURITY 与源码冲突时，以源码和配置为准。
工程手册记录现状与边界，不把历史示例升级成新实现。重大取舍写入 ADR，普通修复写进对应章节。
