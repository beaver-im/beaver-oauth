# 9.3 文档维护

[返回本章](README.md) · [全书目录](../README.md)

## 固定结构

一章一个 `NN-主题/` 目录；章首 `README.md` 首行 `# 第N章`；小节 `NN-主题.md` 标题 `# N.M 主题`。
`docs/README.md` 必须列出全部章和小节。`directory.md` 是现状地图，`glossary.md` 只收易混术语。
产品需求、授权流程流水账和一次性排障记录不进工程手册。

## 变更同步

新增/删除/改名 `docs/**/*.md` 时同任务更新：

1. 章首小节目录；
2. `docs/README.md` 全书目录；
3. `docs/knowledge-checks.json` 的 documents/chapters/requiredPaths；
4. `AGENTS.md` 的硬约束或任务入口；
5. 受影响的 directory、glossary、ADR。

执行 `node scripts/check-knowledge.mjs`，要求 0 failures。
脚本只校验登记、本地链接、章序、源码路径和 AGENTS 行数，不检查技术断言或构建。

## 写作规则

- 命令只写 `package.json` 真实脚本；注明 lint/版权头会改文件。
- API 只写当前实现，不把旧 OAUTH_README 的 code 换 token 当成本仓能力。
- 明确“服务端支持”与“前端已调用”的区别，尤其 qrcode_status。
- 已知缺口写清影响与边界，不用删除文件或登记项掩盖。
- 跨仓链接按实际相对层级核对；不硬编码本机绝对路径。

## 评审重点

检查环境键、端口、mode、包名/仓库名、路由、公开端点和错误处理是否与源码一致。
不得把文档通过表述为测试通过、安全审计通过或完整 OAuth 流程通过。
